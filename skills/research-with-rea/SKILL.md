# Skill: Research with REA

## Use when
The task requires investigating a reference application, understanding unfamiliar product behavior, or recreating a feature based on observable evidence.

Repository: https://github.com/morluto/rea

## Workflow
1. Confirm the target is authorized for inspection and do not bypass access controls.
2. Define the narrow research question and user journey.
3. Use REA according to its current installation and usage documentation; do not assume commands or flags.
4. Capture observable behavior, screenshots/evidence where supported, inputs, outputs, states, and edge cases.
5. Label findings as observed, inferred, or unknown.
6. Convert findings into a behavior specification and acceptance criteria.
7. Design an original implementation compatible with the target project's architecture and design direction.
8. Verify the implementation against the specification, not merely visual resemblance.

## Deliverable
- Feature summary
- User journey and state transitions
- Observed behavior and evidence
- Edge cases and failure states
- Inferences and open questions
- Proposed implementation and acceptance criteria

Do not copy proprietary source code, private data, or protected assets without authorization.
